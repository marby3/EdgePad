# EdgePad 仕様書

2026年10月22日 · @まーびい

## 1. 概要

EdgePadは、画面の上下左右の端にタッチ・マウス操作できるマクロキーパッドを出す、Windows向けの軽量常駐ソフトです。CLIP STUDIO PAINT（以下CSP）のエッジキーボードはiPad/Androidでしか使えないため、同等の操作感をデスクトップOS、特に液晶タブレットやタッチ対応PCで実現します。

- 目的: 片手（指）で修飾キーやショートカットを押しながら、もう片手（ペン）で描ける環境をデスクトップで作る
- 方針: CSP専用にはせず、前面アプリに普通のキー入力を送る汎用ツールにする。アプリごとにキー配置を自動で切り替える
- 最重要の非機能要件: 待機時CPU 0%、メモリ数MB、単体exe1本

用語:

| 用語 | 意味 |
|---|---|
| パネル | 画面端に表示されるキーの並び（上下左右それぞれ1枚） |
| ハンドル | パネル非表示時に画面端に残る細い帯。ここをスワイプ/タップしてパネルを出す |
| キーセット | 1枚のパネルに並べるキーの定義一式 |
| プロファイル | 前面アプリ（プロセス名）とキーセットの対応 |
| ラッチ | 修飾キーを押しっぱなし状態で固定すること |

## 2. 参考：CSPのエッジキーボード

CSP版の「修飾キー＋タッチキー1〜15、端からのスワイプで表示」という骨格はそのまま踏襲します。半透明は、手動の操作ではなく、下が見えた方がいい場面で自動で使います。公式マニュアルでも、Windowsタブレットとタッチ対応の液晶タブレットでは使えないと明記されています（公式マニュアル）。

| 項目 | CSP（iPad/Android） | EdgePad |
|---|---|---|
| 対応環境 | iPad / Androidタブレット | Windows 10/11（将来 macOS / Linux） |
| 表示位置 | 左右の端 | 上下左右の4辺、辺ごとに独立 |
| 固定キー | Esc / Ctrl / Shift / Alt（option）/ Space（iPadはcommandも） | 既定は同じ並び。全キー自由に変更可 |
| タッチキー | 1〜15。CSPのショートカット設定で割り当て | キー自体にキー送出・マクロ等を定義（CSP側の設定不要） |
| 表示 | 端から内側へスワイプ（Androidは切替ボタン） | ハンドルのスワイプ/タップ、ホットキー、マウスの端ホバー、トレイ |
| 半透明表示 | 短いスワイプで半透明。指は操作可、ペンは下のキャンバスへ | 手動では切り替えない。パイメニュー表示中とペンが乗っている時だけ自動で半透明。ペンは透過させず、キーにも反応しない |
| 非表示 | 端の方向へスワイプ | 同じ。加えてホットキー・自動非表示 |
| 対象アプリ | CSPのみ | 前面の任意アプリ。アプリ別に自動切替 |

CSPのタッチキー1〜15はアプリ内部の特殊キーなので、外部ソフトから同じキーは作れません。代わりに、各キーに「Ctrl+Z を送る」のような動作を直接持たせます。CSP側のショートカットに割り当てたい場合は、通常のキーボードにないF13〜F24を送る運用も選べます（CSPのショートカット設定で登録できることを確認済み）。

## 3. 対象環境と技術方針

Rust＋Win32 APIの直接呼び出しで作り、GUIフレームワークやランタイム（.NET、Electron、WebView）は一切使いません。これがメモリ数MB・exe 1MB以下に収める前提です。

| 項目 | 方針 |
|---|---|
| 初期対象OS | Windows 10 21H2以降 / Windows 11（x64。ARM64は優先度低） |
| 言語 | Rust（stable）。依存クレートは windows-sys のみを原則とする |
| 描画 | GDI＋UpdateLayeredWindow（32bit DIBでアルファ付き）。変化があった時だけ再描画 |
| 入力受付 | WM_POINTER 系メッセージ。タッチ・ペン・マウスを種別付きで受ける |
| キー送出 | SendInput（仮想キー、文字は KEYEVENTF_UNICODE） |
| 前面アプリ検出 | SetWinEventHook(EVENT_SYSTEM_FOREGROUND)。ポーリングしない |
| 設定 | テキストのINI風ファイルを自前パーサで読む（serde/toml を入れない） |
| ビルド | opt-level="z"、LTO、codegen-units=1、panic="abort"、strip、CRT静的リンク |
| 配布 | 単体exe＋設定ファイル1つ。インストーラなし、ポータブル動作可 |

将来のmacOS/Linux対応に備え、OSに依存しない「コア」と、OSごとの「プラットフォーム層」を分けます。コアはキー定義・修飾キーの状態管理・レイアウト計算・設定読込を持ち、OS APIを呼びません。

| 層 | 担当 | Windows実装 | 将来の移植先 |
|---|---|---|---|
| コア | 設定、キーセット、修飾キー状態機械、レイアウト、ジェスチャ判定 | 共通 | 共通 |
| ウィンドウ/描画 | 前面固定・非アクティブのパネル、ハンドル | Win32＋GDI | macOS: 非アクティブNSPanel / Linux: X11 override-redirect、Wayland layer-shell |
| キー送出 | 仮想キーの押下・解放 | SendInput | macOS: CGEventPost（アクセシビリティ許可が必要）/ X11: XTest / Wayland: uinput か libei |
| 前面アプリ検出 | プロファイル切替 | WinEventHook | macOS: NSWorkspace通知 / X11: _NET_ACTIVE_WINDOW |
| 常駐UI | トレイアイコン、ホットキー | Shell_NotifyIcon、RegisterHotKey | 各OSの同等機能 |

Waylandはセキュリティ上、他アプリへのキー送出と前面アプリ取得に標準手段がないため、Linux対応はX11を先に行います。

入力から送出までは1本のメッセージループで処理します。設定変更と前面アプリの切替は、コアが持つキーセットを入れ替えるだけです。

## 4. 機能要件

### 4.1 パネルと常駐

- 上下左右の各辺にパネルを1枚ずつ持てる。辺ごとに有効/無効、対象モニタ、キーセットを設定する
- 起動するとタスクトレイに常駐し、タスクバーには出ない
- トレイメニュー: 各辺の表示切替、プロファイル一時固定、設定…（設定画面を開く、7.1）、設定ファイルを開く、設定再読込、一時停止、全キー解放、Windows起動時に自動起動、終了
- 多重起動しない（名前付きミューテックス）。2回目の起動は既存インスタンスのパネル表示切替として扱う

### 4.2 キーの種類

| 種類 | 動作 | 例 |
|---|---|---|
| modifier | 押している間だけ押下。短くタップするとラッチ（再タップで解除） | Ctrl, Shift, Alt, Win |
| hold | 押している間だけ押下。ラッチしない | Space（手のひらツール） |
| shortcut | 離した時に1回送出。ラッチ中の修飾キーと合成 | Ctrl+Z, Ctrl+Shift+S |
| repeat | 押している間オートリピート | [ ]（ブラシサイズ）, 矢印 |
| macro | 複数のキー操作を待ち時間付きで順に送出 | Ctrl+A → Ctrl+C |
| text | 文字列をUnicode入力で送る | 定型文 |
| run | プログラムやURLを起動 | 電卓、資料フォルダ |
| page | パネル内のページ切替、別キーセットへ切替 | 次ページ |
| pie | 押した位置にパイメニューを開き、滑らせた方向の項目を離した時に実行 | 変形メニュー |
| layer | 押している間だけ、または押すたびに、パネルを別のキーセットに切り替える（レイヤー） | Raise, Lower |

### 4.3 修飾キーの挙動

指で押さえたままペンで描く使い方を最優先にします。マウス操作では「押さえたまま他を操作」ができないため、タップでのラッチを必須とします。

| 操作 | 結果 |
|---|---|
| 押して離す（250ms未満、他のキー操作なし） | ラッチ。キーは押下状態のまま強調表示 |
| ラッチ中にもう一度タップ | 解除（キーアップ送出） |
| 押したまま（250ms以上） | 押している間だけ押下。離すとキーアップ |
| ラッチ中にshortcutキーを押す | 合成して送出後、ラッチを自動解除（ワンショット）。常時固定は設定で選択 |
| パネル非表示、プロファイル切替、画面ロック、終了 | 押下中の全キーを必ず解放 |

### 4.4 キーセットとプロファイル

- キーセットはページを持てる。表示しきれないキーは次ページへ送る
- キーセットは、辺に沿って並べる（既定）ほかに、キーを好きな位置・幅・高さで置いた自由配列にできる。自由配列は手で書くか、Keyboard Layout Editor（KLE）で組んだ配列を読み込む（7 章）。自由配列は全キーを1ページで出す
- プロファイルはプロセス名（例: CLIPStudioPaint.exe）で前面アプリと照合し、辺ごとのキーセットを自動で切り替える
- どのプロファイルにも当たらない時は default を使う。プロファイル側で「このアプリではパネルを出さない」も指定できる
- トレイから現在のプロファイルを一時固定できる（ダイアログ操作中の誤切替防止）

### 4.5 表示・非表示の操作

| 操作 | 結果 |
|---|---|
| ハンドルから内側へスワイプ（キー半分以上） | 表示 |
| パネル上で端の方向へスワイプ | 非表示（半透明時も同じ） |
| パネル上で内側へ素早く払う | 何もしない（押したキーは指を離すまで押されたまま） |
| パイメニューを開いている間 | 表示中のすべての辺のパネルを半透明（dim_opacity）に。パイメニュー自身は通常の不透明度。閉じると戻る |
| ペンがパネルの上にある間（ホバー） | そのパネルだけ半透明に。パネルの外へ出るか検出範囲から離れると戻る。指やマウスでは薄くならない |
| ハンドルをタップ / クリック | 表示切替 |
| マウスを辺に一定時間当てる（任意） | 表示。離れて一定時間で非表示 |
| グローバルホットキー（例: Ctrl+Alt+E） | 全辺の表示切替 |
| 最後の操作から一定時間（任意、既定オフ） | 自動で非表示 |

### 4.6 パイメニュー

pie キーは、別のキーセットを項目にしたパイメニューを開きます。パネルに並べきれない操作を、1キー分の場所から方向で選べるようにします。

- 項目は参照先キーセットのキーを先頭から順に使う。キーは2〜8個で、それ以外は読込エラー（9個以上のセットの先頭8個だけを使うことはしない）。項目の種類は shortcut / macro / text / run / page と、何も送らない none に限る（離した時に1回実行するため。none は選んで離すと何もせず閉じる）。modifier / hold / repeat / pie / layer と、項目数の誤りは読込エラー
- 押した位置から画面の内側へ向けて扇形に開く（左辺なら右半分）。項目は扇の角度を等分して並べる
- 方向の判定は押した位置からの移動量で行う。中央（半径はキー1辺の半分）と、端の側（扇の外）で離すと取消

| 操作 | 結果 |
|---|---|
| pie キーを押したまま滑らせて離す | 指している項目を実行して閉じる |
| 中央または端の側で離す | 何もせず閉じる |
| タップ（中央から動かさずに離す） | 開いたまま。項目をタップで実行、中央か pie キーのタップで閉じる |
| ラッチ中の修飾キーがある | shortcut と同じく合成して送出、ワンショット解除 |
| パネル非表示、プロファイル切替、画面ロック、スリープ、終了 | 何も実行せず閉じる |

- pie キーを押している指は、端の方向へ動かしてもパネルを隠さない（4.5 のフリックの対象外）
- ペンでは開かない（pen_presses の設定に従う）
- 開いたままの時に扇の外をタップしても閉じない。その入力は下のアプリへ届き、パイメニューは入力を奪わない

## 5. UI仕様

### 5.1 ハンドル

- 非表示時、有効な辺に幅4〜8px（設定可）の細い帯を出す。長さは辺の中央40%を既定とし、位置と長さは設定で変更できる
- Windowsのタッチ環境では画面端からのスワイプがOS（ウィジェット、通知センター等）に取られる。このためハンドルは画面のきわではなく、ハンドル自体を起点にしたスワイプで判定する
- 下端からのスワイプ（スタートメニュー）はポリシーで止められないため、下の辺はパネルとハンドルを画面の端から既定で 16 論理px 離して置く。離す距離は辺ごとの `gap`（論理px、0〜64、DPI に比例）で変えられ、上・左・右の辺の既定は 0。離した間の帯はマウスだけが受け、マウスを画面の端に当てて出す操作（hover_ms）はそのまま効く。指でこの帯に触れてもハンドルとしては扱わない。ドックする辺は、この隙間も含めて空ける
- ハンドルは描画をほぼ持たない（単色＋不透明度30%程度）。不要なら非表示にしてホットキーのみで運用できる

### 5.2 パネル

- 左右のパネルは縦並び、上下のパネルは横並び。列数（左右）と行数（上下）は1〜3で設定
- キーは正方形を基本とし、1辺は既定56論理px（DPIに比例）。キーごとに幅を2倍などに広げられる
- 自由配列のキーセットは、置いたとおりの位置・幅・高さで描き、パネルは全キーを囲む大きさにする（列数・行数は効かない）。上下の辺では組んだとおりの向きで置く。左の辺では時計回りに、右の辺では反時計回りに 90° 回し、下の辺と同じく配列の下の行を画面の端の側に向ける（行の左端は、左の辺では上、右の辺では下になる）。ラベルの文字はどの辺でも回さない。辺に収まらないほど大きい配列は、はみ出した分が画面の外に出る
- 表示要素は「ラベル文字」「押下状態」「ラッチ状態」の3つだけ。アイコン画像は後回し（必要ならPNG読込を拡張で追加）
- 配色はライト/ダーク2種＋アクセント1色。OSのダークモード設定に追従（任意）
- 通常表示の不透明度は既定100%（不透明）。パイメニュー表示中とペンが乗っている時の不透明度（dim_opacity）は既定35%
- 表示/非表示はアニメーションなし（軽さ優先）。任意で100ms程度のスライドを選べる

### 5.3 ウィンドウ属性

| 属性 | 目的 |
|---|---|
| WS_EX_NOACTIVATE | 押してもフォーカスを奪わない。キーが前面アプリに届く前提 |
| WS_EX_TOPMOST | 常に最前面 |
| WS_EX_TOOLWINDOW | タスクバー・Alt+Tabに出さない |
| WS_EX_LAYERED | アルファ付き描画、半透明表示 |

### 5.4 モニタとDPI

- Per-Monitor DPI Aware V2 を宣言し、モニタ移動やスケール変更（WM_DPICHANGED）で再レイアウトする
- 辺ごとに対象モニタを primary / 番号 / cursor（表示時にカーソルがあるモニタ）から選ぶ
- モニタ構成の変更（WM_DISPLAYCHANGE）で位置を再計算する

### 5.5 ドッキングモード（任意）

既定はキャンバスの上に重ねるオーバーレイ表示です。設定で辺をAppBar（SHAppBarMessage）として登録すると、最大化ウィンドウがパネルの分だけ縮み、キャンバスを隠しません。デスクトップならではの選択肢として用意します。

### 5.6 パイメニュー

- パネルと同じ属性（5.3）の窓を、開いている間だけ作る。閉じたら窓と描画バッファを解放する
- 押した位置を中心とする半円のドーナツ形のタッチエリアを、項目ごとの扇形の区画に分ける。区画の外は透明
  - 区画どうしはパネルのキーの間と同じ幅のすき間で区切る。中央の取消範囲（半径はキー1辺の半分）は穴として抜く
  - 外径はキー2個分以上。項目が多い時は、ラベルを置く位置（穴と外周の中間）で区画の幅がキー1個分以上になるまで大きくする
  - 縁は1ピクセルずつ覆う割合を計算して滑らかに描く（GDIの扇形はアンチエイリアスが効かないため使わない）。ラベルの文字だけGDIで描く
- 表示要素は区画と項目のラベル文字、指している項目の強調だけ。区画はキーの面、強調は押しているキーと同じ色。配色と不透明度はパネルに合わせる
- 開く時に遅延やアニメーションは入れない。タイマーを使わない

## 6. キー送出とフォーカス制御

パネルはフォーカスを持たず、SendInput で送ったキーはそのとき前面にあるアプリ（例: CSP）に届きます。押下状態はOS全体で共有されるため、指でCtrlを押さえている間にペンでキャンバスを操作すれば、CSPからはCtrl＋ペン操作に見えます。

### 6.1 入力の受け方

- WM_POINTERDOWN / UPDATE / UP を使い、ポインタIDごとに追跡する。複数の指で複数キーを同時に押せる
- ポインタ種別（タッチ / ペン / マウス）ごとに「キーを押せるか」を設定できる。既定はタッチとマウスのみ可、ペンは不可（誤タッチ防止）
- 押したままキーの外へ指が出ても、指を離すまで押下を維持する（描画中の手のずれ対策）
- パネルへのタッチがOSのマウス操作に変換されないよう、ポインタメッセージを自前で処理して既定処理へ流さない

### 6.2 送出の規則

- 修飾キーの押下は、自分が送ったものだけを記録して管理する。物理キーボードで押されている修飾キーには触れない
- shortcutは「ラッチ中修飾キー＋定義上の修飾キー」を押下 → 本キー押下 → 本キー解放 → 定義上の修飾キー解放、の順に送る
- 拡張キー（矢印、Insert、Delete等）は KEYEVENTF_EXTENDEDKEY を付け、スキャンコードも併せて送る（ゲーム系・一部アプリ対策）
- 送出イベントには独自の dwExtraInfo 値を付け、自分の入力と区別できるようにする

### 6.3 押しっぱなし事故の防止

キーが押下されたまま残ると、OS全体の操作が狂うため最優先で防ぎます。

- パネル非表示、プロファイル切替、WM_WTSSESSION_CHANGE（ロック・ユーザー切替）、スリープ移行、終了の各時点で、自分が押下中の全キーを解放する
- パニック時もフックで解放してから終了する（panic="abort" でもパニックフックは実行される）
- トレイメニューに「全キー解放」を置く

### 6.4 権限の制約

Windowsの仕様（UIPI）により、通常権限のEdgePadからは管理者権限で動くアプリへキーを送れません。管理者アプリに使う場合はEdgePadも管理者で起動する必要があります。設定ドキュメントに明記し、送出に失敗した時はトレイ通知で知らせます。

## 7. 設定ファイル仕様

設定はUTF-8のテキスト1ファイル（edgepad.ini）で行います。テキストエディタで直接書くほか、本体に内蔵した設定画面（7.1）でも全項目を編集できます。exeと同じフォルダに置けばポータブル動作、なければ %APPDATA%\EdgePad\edgepad.ini を使います。

- 保存を検知して自動で再読込する（FindFirstChangeNotification、待機はイベント駆動）
- 読込エラー時は直前の設定のまま動き続け、トレイ通知に行番号と理由を出す
- キー名はWindowsの仮想キー名に準じた英字表記（Ctrl, Shift, Alt, Win, A〜Z, F1〜F24, Space, Enter, Esc, Left, PgUp 等）。+ で組み合わせる。テンキーは Numpad0〜Numpad9, Multiply, Add, Subtract, Decimal, Divide。JIS 配列にしかないキーは Hankaku（半角/全角）, Henkan（変換）, Muhenkan（無変換）, Kana（カタカナひらがな）, Ro（ろ）。JIS 配列のほかのキーは、Windows が同じ仮想キーとして送る US 配列のキーの名前で書く（@ は `、¥ は \、^ は '、; は =、: は ;）
- 1行1キーで `key = ラベル | 種類 | 内容 | オプション` と書く

```ini
[general]
hotkey        = Ctrl+Alt+E   ; 全辺の表示切替
key_size      = 56           ; キー1辺（論理px）
opacity       = 100          ; 通常表示の不透明度 %
dim_opacity   = 35           ; パイメニュー表示中とペンが乗っている時の不透明度 %
latch_ms      = 250          ; これ未満のタップでラッチ
pen_presses   = false        ; ペンでキーを押せるか
theme         = auto         ; light / dark / auto

[edge.left]
enabled  = true
monitor  = primary           ; primary / 1,2... / cursor
columns  = 1
handle   = 6, 40%            ; ハンドル幅px, 長さ
gap      = 0                 ; 画面の端から離す距離（論理px、0〜64。下の辺の既定は 16）

[edge.right]
enabled  = true
monitor  = primary
columns  = 2

[set.mods]
key = Esc   | shortcut | Esc
key = Ctrl  | modifier | Ctrl
key = Shift | modifier | Shift
key = Alt   | modifier | Alt
key = Space | hold     | Space

[set.csp-tools]
key = 元に戻す | shortcut | Ctrl+Z
key = やり直し | shortcut | Ctrl+Y
key = ブラシ小 | repeat   | [        | interval=60
key = ブラシ大 | repeat   | ]        | interval=60
key = 選択解除 | shortcut | Ctrl+D
key = 左右反転 | shortcut | F13      ; CSP側でF13に割り当てる運用
key = 保存     | macro    | Ctrl+S, wait 300, Esc
key = 次へ     | page     | next
key = 変形     | pie      | csp-transform

[set.csp-transform]                ; pie の項目（先頭から2〜8個）
key = 拡大縮小 | shortcut | Ctrl+T
key = 上下反転 | shortcut | F14
key = 回転戻し | shortcut | F15
key = 確定     | shortcut | Enter

[profile.default]
left  = mods

[profile.csp]
process = CLIPStudioPaint.exe
left    = mods
right   = csp-tools
```

キーセットは複数の辺で共有できます。none を指定した辺はそのプロファイル中は表示しません。

キーセットに `layout` を書くと、キーを辺に沿って並べずに、自由な位置に置けます（自由配列）。

```ini
[set.pad]
layout = free                         ; 位置はキーごとに書く
key = Esc   | shortcut | Esc   | x=0,    y=0
key = Space | hold     | Space | x=1.25, y=0, w=2, h=0.75

[set.csp-pad]
layout = kle:csp-pad.json             ; 位置は KLE のファイルから読む
key = 元に戻す | shortcut | Ctrl+Z
key = やり直し | shortcut | Ctrl+Y
```

- `layout = free` のキーセットでは、各キーのオプションに `x=`, `y=`（位置）と `w=`, `h=`（幅と高さ。既定 1）を書きます。単位はキー1つ分（key_size）で、0.25 刻みです。x と y は 0〜40、w と h は 0.25〜8 です。x と y はすべてのキーに要ります
- `layout = kle:ファイル名` のキーセットは、そのファイルの KLE の raw data（KLE の Raw data 欄の文字をそのまま保存したもの、または KLE からダウンロードした JSON）から、キーの位置・幅・高さを読みます。ファイル名は設定ファイルのフォルダからの相対パスか、絶対パスで書きます。KLE で左や上にはみ出して置いたキーも読み、配列全体を左上に寄せます。KLE のキーは、上の行から順に、行の中は左から右へ、key 行に1つずつ割り当てます。key 行が足りないキーは、KLE のラベル（最初に書いたもの）を出すだけで何も送りません。key 行には x・y・w・h を書きません
- 何も送らないキーは、種類に `none` と書けます（内容は何でもよく、`-` などと書きます）。設定画面で KLE の配列を自由配列にすると、key 行が足りなかったキーをこの形で書き出します
- 回転したキー（r, rx, ry）は、KLE と同じ位置と角度で読み、パネルにも設定画面の見本にもその角度で描きます。押せるのは回したキーの形の内側だけです。自由配列に変えると、回したキーは同じ真ん中と大きさのまま回転を外して置きます（key 行には角度を書けないため）
- 読込エラーになるもの: key 行が配列のキーより多い（その key 行）。KLE のファイルがない・読めない・KLE の raw data として読めない（layout の行）。KLE の色・フォントなどの見た目の指定は読み飛ばします
- 設定ファイルのフォルダにある KLE のファイルを保存し直すと、設定ファイルと同じく読み直します
- `layout` を書いていないキーセットは、今のとおり辺に沿って並べます。x・y・w・h はそこでは書けません

layer キーは、パネルを別のキーセット（レイヤー）に切り替えます。

```ini
[set.base]
key = Raise | layer | raise                 ; 押している間だけ raise
key = 数字  | layer | num   | mode=toggle   ; 押すたびに num と切り替え

[set.num]
key = 7    | shortcut | 7
key = 戻る | layer    | num | mode=toggle   ; 押すと base に戻る
```

- 内容に切り替え先のキーセットを書きます。`mode=hold`（既定）は押している間だけ切り替え、押した指（またはマウスのボタン）を離すと戻ります。`mode=toggle` は押すと切り替え、切り替えた先にある、そのキーセットを指す toggle の layer キーを押すと戻ります
- 戻る先は、プロファイルでその辺に決まったキーセット（page キーで切り替えていれば、そのキーセット）です。切り替えた先の layer キーも同じように働きます
- 修飾キーの押下とラッチは、切り替えをまたいで残ります（切り替えた先の shortcut と合成し、ワンショットなら送ったあとに解除）。切り替える時、押していた hold と repeat のキーは離します
- パネルを隠した時とプロファイルが変わった時は、元のキーセットに戻り、押していたキーは 6.3 のとおりすべて解放します
- パネルの形は、切り替えた先のキーセットの並びになります
- 指すキーセットがない、mode が hold・toggle 以外、パイの項目に layer キーがある時は、読込エラーです

`[edge]` には全辺に共通の設定を書けます。書ける項目は `[edge.*]` と同じで、columns は左右の辺に、rows は上下の辺に効きます。`[edge.left]` などに書いた項目は、その辺だけで `[edge]` より優先します。辺にも `[edge]` にも書いていない項目は既定値です。設定画面では、`[edge]` を「辺（共通）」で編集します。「辺ごとの設定」では、辺に書いていない項目に `[edge]` の値を「共通」と添えて出し、「共通に戻す」はその辺の行を消して共通の値に戻します。

### 7.1 設定画面

設定ファイルの全項目を、テキストを書かずに編集する画面です。別exeやWebページにはせず本体に内蔵します。

- トレイメニューの「設定…」で開く通常のウィンドウ。同じ exe を、設定画面だけを出す2つ目のプロセスとして起動して出す（パネル・トレイアイコン・ホットキーは持たず、多重起動防止にも当たらない）。開いている間はこのウィンドウだけタスクバーと Alt+Tab に出る。すでに開いていれば、そのウィンドウを前に出す（二重には開かない）
- 設定画面が前面になっても、プロファイルは切り替えない（EdgePad 自身のウィンドウは 4.4 の前面アプリとして数えない）。キーの押下もそのまま
- ボタン・入力欄・ドロップダウン・チェックボックス・一覧・サイドバーには OS 標準の部品を使う（Windows は comctl32 v6 の見た目）。自前で描くのは、パネルの見本や画面の図のように標準の部品にないものだけにする。comctl32 v6 は設定画面を初めて開いた時に読み込み、起動時には読み込まない
- 窓の左のサイドバーに「キー配置」「キーマッピング」「アプリ別」「辺（共通）」「辺ごとの設定」「見た目」「タッチと修飾キー」「表示と非表示」の8項目が並び、選んだ画面が右側に出る。開いた時は「キー配置」を出す。画面は設定ファイルの章立てではなく、やりたいことで分け、合わせて全項目を編集できる
  - キー配置: キーセットと、パネルの形（[set.*] の layout と、キーの数・並び・幅・位置）
  - キーマッピング: 各キーが何を送るか（[set.*] の key 行のラベル・種類・内容と、種類ごとのオプション）
  - アプリ別: プロファイル（[profile.*]）
  - 辺（共通）: 全辺に共通の項目（[edge]）。表示する（enabled）、画面の端を空ける（dock）、画面の端からの距離（gap）、モニター、列数（左右の辺の columns）、行数（上下の辺の rows）、ハンドル（handle）
  - 辺ごとの設定: 画面の図で選んだ辺だけの項目（[edge.*]）。辺に書いていない項目は [edge] の値を「共通」と添えて出す
  - 見た目: キーの大きさ（key_size）、ふだんの不透明度（opacity）、パイメニュー・ペンの時の不透明度（dim_opacity）、テーマ（theme）、アクセント色（accent）、出入りの時間（slide_ms）
  - タッチと修飾キー: ラッチになる長さ（latch_ms）、ラッチの解け方（latch）、ペンでキーを押す（pen_presses）
  - 表示と非表示: ホットキー（hotkey）、ハンドルに乗せて出すまでの時間（hover_ms）、自動で隠すまでの時間（auto_hide_ms）
- 「キー配置」と「キーマッピング」は、上部で編集するキーセットをドロップダウンで選ぶ。選んでいるキーセットとキーは、2 つの画面で共通
- 両方の画面に（「キー配置」では左に、「キーマッピング」では上に）、パネルの見本を、パネルと同じ色・形・キーの幅で描く。並びと向きは、そのキーセットを使っている最初の辺に合わせる（列数・行数もその辺のもの）。見本の場所の中で、その辺の側に寄せる（右辺なら右端、下辺なら下端）。上下の辺はそのまま、左辺は時計回り、右辺は反時計回りに回して描く（パネルと同じ）。自由配列と KLE のキーセットは、その配列の形で描く。どの辺でも使っていないキーセットは、左辺として描く。見本のキーを押すか、見本にフォーカスがある時に矢印キーで、キーを選ぶ。選んだキーは押されたキーの色で、重なったキーの上に描く
- 「キー配置」は、パネルの形を組む
  - キーセットのドロップダウンの横の「追加」「名前の変更」「削除」で増やす・名前を変える・消す。「KLE から読み込む」を押すとファイルを選ぶ画面が開き、選んだ KLE のファイルを設定ファイルのフォルダに写して、選んでいるキーセットに `layout = kle:写したファイル名` を書く（保存は「保存」で）。今の key 行の割り当てはそのまま残し、key 行の x・y・w・h は消す（位置は KLE のファイルから読むため）。フォルダに同じ名前で別の中身のファイルがある時は、上書きするかを尋ねる。KLE の配列として読めないファイルは写さず、理由をステータス行に出す。その下に、そのキーセットを使っている場所（「csp の右辺」「変形キーのパイ」など）を出す。名前を変えると、使っている辺・page キー・pie キー・layer キーの参照も新しい名前になる。使っている場所のあるキーセットは削除せず、使っている場所を示して先に外すよう伝える
  - 見本の下のボタンで、キーの追加・削除・並べ替え（↑ / ↓）をする。Alt+↑ / Alt+↓ でも並べ替える。追加したキーは、選んでいるキーの後ろに入る（`layout = free` のキーセットでは、ほかのキーの下の行の左端（x=0）に置く）
  - 見本の右に「並べ方」のドロップダウンを出す。「辺に沿って並べる」「自由配列」と、`layout = kle:…` のキーセットでは「KLE（ファイル名）」。どの切り替えでも、ラベルと割り当ては残す
    - 辺に沿う並びから自由配列にすると、`layout = free` を書き、見本に描いていた並びを、上下の辺の向きにした位置として、各キーの行に x・y・w・h で書く
    - 自由配列か KLE から辺に沿う並びにすると、`layout` の行と各キーの x・y・w・h を消し、キーを位置の (y, x) の順に並べ、w を四捨五入して 1〜3 に収めた値を width に書く
    - KLE から自由配列にすると、ファイルの位置を各キーの行に写し、`layout = free` にする。key 行が足りないキーは `none` のキー（5.2）として書き足す
  - 辺に沿う並びでは、その下に選んだキーのキーの幅（width、1〜3）の欄を出す
  - 自由配列では、選んだキーの x・y・w・h の欄を出す。刻みは 1/4 キー、範囲は x・y が 0〜40、w・h が 0.25〜8。見本の上でキーをドラッグすると動き、選んだキーの右端か下端をドラッグすると幅か高さが変わる。どちらも 1/4 キーの刻みに吸い付き、離した時にそのキーの行だけを書き換える。見本は辺の向きに回して描くが、ドラッグは画面の見た目どおりの向きに効く（左辺の見本で上にドラッグすると、配列の中でもその向きに動く）
  - KLE のキーセットでは、x・y・w・h の欄は読むだけで、ドラッグもできない。欄の下に「並べ方を自由配列にすると動かせます」と出す
- 「キーマッピング」は、各キーが何を送るかを決める。Vial のように、上にキー配置の絵、下にキーボードの絵と分類のタブを出し、上で選んだキーに下から割り当てる。上から順に次のものを置く
  - キーセットのドロップダウンと、レイヤーのタブ。タブには、ドロップダウンで選んだキーセットと、そのレイヤーキーが指すキーセットを、指した先のレイヤーキーが指すものも含めてたどれる順に並べる（同じキーセットは 1 回だけ。16 個まで）。タブを選ぶとそのキーセットの絵と欄に切り替わり、選んだキーの番号はそのまま保つ（そのキーセットにその番号がなければ先頭のキー）
  - キー配置の絵（見本）。画面の幅いっぱいに描く。高さは下のキーボードの残りで、キーはその中に収まる大きさで描く。見本にフォーカスがある時は、矢印キーで前後のキーを、Home / End で先頭と最後のキーを選ぶ
  - 選んだキーのラベルの欄（パネルのキーの幅に収まらない時は、打っている間に「パネルでは切れます」と出す）と、今の割り当てを一文で表したもの（「Ctrl+Z を送る」「押している間 Space」「num に切り替える（押している間）」など）
  - 修飾キー（Ctrl / Shift / Alt / Win）のオン / オフと、動きの 3 つ（「押した時に送る」「押している間」「連打」）、連打の時だけ間隔の欄（20〜1000 ms）、「押して取り込む」。下のキーを押すと、その時の修飾キーと動きで割り当てる（押した時に送る: shortcut、押している間: hold でキー 1 つ（修飾キーは使わない）、連打: repeat）。修飾キーか動きを変えると、選んだキーの割り当てもすぐその形に変わる。「押して取り込む」を押すと取り込み中の表示になり、次に押したキーの組み合わせが入る（もう一度押すと取りやめ）。「表示と非表示」画面のホットキーの欄にも「押して取り込む」を付ける
  - 分類のタブ「基本」「JIS」「レイヤー」「マクロ」「文字・起動」「ページ・パイ」と、その中身。Shift で別の記号になるキーのボタンは、上の段に Shift の記号、下の段にそのキーを描く（上が「!」、下が「1」）
    - 基本: 英数字・記号・F1〜F24・Esc・Tab・Enter・Backspace・Space・移動と編集のキーを、US 配列のキーボードに近い並びのボタンで描く。その右にテンキーの並びのボタン、テンキーの上に Ctrl / Shift / Alt / Win のボタンを置く。修飾キーのボタンを押すと modifier（ラッチする修飾キー）になる
    - JIS: 「基本」と同じ作りと大きさで、JIS 配列の並び（半角/全角、¥、@ と [、; と : と ]、ろ、無変換・変換・カタカナひらがな、2 段の高さの Enter）のボタンを、JIS の刻印で描く。テンキーと修飾キーのボタンは「基本」と同じ位置。ボタンを押すと、そのキーと同じ仮想キーのキーを割り当てる（キー名は上のとおり）。JIS 配列にしかないキーを送るキーを選ぶと、このタブを開く
    - レイヤー: ほかのキーセット（編集しているもの以外）の一覧と「押している間 / 押すたびに切り替える」。選ぶと layer キーになる
    - マクロ: 手順の一覧（キー操作か待ち時間、追加・削除・並べ替え）と、待ち時間の欄（0〜10000 ms）。手順を追加すると macro キーになる。選んだ手順のキーは「押して取り込む」か、基本のボタンで入れる（待ち時間の手順を選んでいる時は入れず、理由を出す）。手順が 2 つ以上あるマクロは、動きを選んでも変えない（手順を 1 つにしてから）
    - 文字・起動: 送る文字列の欄と、パスか URL の欄。打って確定した方の text / run キーになる
    - ページ・パイ: page の切り替え先（次 / 前 / キーセット）と「パイにする」。「パイにする」を押すと選んだキーを pie にし、項目用のキーセットを `[set.pie-ラベル]` の名前で作る（キーセットの名前は英数字なので、ラベルの英数字だけを使う。英数字がなければ `pie`。同じ名前があれば `-2`、`-3` を付ける）。中身は `none` の項目 2 つで、そのあと扇の図を開く。pie のキーでは「項目を編集」と出し、押すと扇の図を開く
  - pie キーを見本で選ぶと、見本の場所に扇の図を出す（パイの項目の編集）
    - 図はパイメニューと同じ形で、パネルを置く最初の辺から開く向きに描く。区画に項目のラベルを描き、選んだ項目は押されたキーの色で描く。最初の項目を選んで開く
    - 区画を押すか、図にフォーカスがある時に矢印キー・Home / End を押すと、項目を選ぶ。下の欄は選んだ項目を編集し、割り当ての手順はパネルのキーと同じ。書き換えるのは項目用のキーセットにあるその項目の行だけ
    - 図の上（レイヤーのタブの場所）に「パネルに戻る」「＋」「削除」と、項目に使えないものの説明を出す。項目に使えない割り当て（動きの「押している間」「連打」、基本の修飾キーのボタン、レイヤーのタブ、「パイにする」）は押せない
    - 「＋」は選んだ項目の後ろに `none` の項目を足して選ぶ（8 個まで）。「削除」は選んだ項目を消す（2 個まで残す）
    - 「パネルに戻る」で見本に戻り、その pie キーを選んだままにする。キーセットのドロップダウンで別のキーセットを選んだ時と、ほかの画面に移った時も見本に戻る
  - pie キーだけが指しているキーセット（項目用のキーセット）は、キー配置とキーマッピングのキーセットのドロップダウン、レイヤーのタブ、レイヤーの一覧、page の切り替え先、アプリ別の辺のドロップダウンに出さない。pie キーを別の種類にするか消すと、項目用のキーセットをほかに指しているものがなければ、そのキーセットも消す。保存に失敗した行が項目用のキーセットにある時は、その pie キーの扇の図を開く
  - キーを選ぶと、その割り当ての分類のタブを開き、送るキーのボタン、修飾キー、動きをオンの見た目にする。修飾キーと動きは次に押すキーにも使い、動きを持たない種類のキーでは「押した時に送る」と修飾キーなしに戻す。割り当てを変えると、ボタンと一文の説明もすぐ変わる
  - 自由配列のキーセットも同じ欄で編集し、`layout` の行とキーの x・y・w・h は残す
  - 欄を変えると、そのキーの行だけを書き換える。ほかの行、コメント、その行の行末コメントは残し、書き換えた欄の前後の空白も残す（短くなった欄は空白で埋め、手で揃えた列を崩さない）。キーとして読めない値は、ほかの画面と同じく欄で止める
- 「アプリ別」は、プロファイルを編集する
  - 左にアプリの一覧を出す。先頭は「既定（ほかのアプリ）」（[profile.default]）で、その下に各プロファイルをプロセス名で並べる。いま効いているプロファイル（設定画面が前面の時は、その前に前面だったアプリのもの。トレイで固定していればそのもの）には ▶ を付ける。常駐側に登録済みのメッセージで尋ね、設定画面が前に出るたびに尋ね直す
  - 一覧の下の「開いているアプリから追加」で、今ウィンドウが見えているアプリのプロセス名を、押した時に1回だけ集めて一覧にする。そこから選ぶか、プロセス名を手で入れて「追加」する。名前はプロセス名から作る（CLIPStudioPaint.exe → clipstudiopaint）。すでにプロファイルのあるプロセス名は追加せず、理由を出す。「削除」でプロファイルを消す。既定は消せない
  - 右に選んだアプリのプロセス名の欄と、画面を表す四角と4辺の図を出す。各辺の上のドロップダウンで、その辺に出すキーセットか「なし」を選ぶ。辺を押すと開き、図にフォーカスがある時は ←→↑↓ で辺を選んで Enter で開く。「なし」は none と書く
  - 欄を変えると、その項目の行だけを書き換える。ファイルにない項目は追加する
- 「辺（共通）」から「表示と非表示」までの5画面は、項目ごとの欄（項目名、設定ファイルでの名前、入力欄、書ける範囲、既定値か「既定に戻す」）。項目名は何を変えるかが分かる日本語にし、設定ファイルでの名前は横に小さく添える。数値と文字は入力欄、選べる値は日本語の名前のドロップダウン、オン / オフはチェックボックス
  - 書ける範囲（「24〜200」など）は、その欄にフォーカスがある時か、マウスがその項目の上にある時だけ出す
  - ドロップダウン: モニターは「主モニター」「マウスのあるモニター」と、つながっているモニター（「モニター 1」…）。テーマは「ライト」「ダーク」「Windows に合わせる」。ラッチの解け方は「1 回使うと解ける」「もう一度押すまで続く」。アクセント色は「Windows に合わせる」「色を指定」で、指定の時だけ #RRGGBB の欄を出す
  - 「辺（共通）」と「辺ごとの設定」の欄は同じ並び。「辺ごとの設定」では左右の辺に列数、上下の辺に行数を出し、「既定に戻す」は「共通に戻す」になる（その辺の行を消し、共通の値に戻す）
  - 「辺ごとの設定」の上部に画面を表す四角と4辺の図を置き、図で選んだ辺の項目を図の下で編集する。図は有効な辺を塗りつぶし、無効な辺を線だけで描き、選んでいる辺を強調し、ハンドルの位置と長さを辺の上に示す。辺を押すか、図にフォーカスがある時に ←→↑↓ で選ぶ。欄を変えると図もすぐに変わる
  - 設定ファイルに書いていない項目は、既定値を「既定値」と添えて出す（辺の項目で [edge] にあるものは、その値を「共通」と添えて出す。7 章）。「既定に戻す」（「辺ごとの設定」では「共通に戻す」）はその項目の行をファイルから消す。開いている間に外での書き換えを読み直すと、欄も新しい値になる
  - 欄を変えると、その項目の行だけを書き換える（ほかの行、コメント、その行の行末コメントは残す）。ファイルにない項目やセクションは追加する
  - 範囲外や形式の違う値は入力欄で止める。欄を誤りの表示にし、ステータス行に理由を出し、ファイルには書かない。文字と数値の欄は Enter かフォーカスが外れた時に確定する
  - 数値の欄は、マウスのホイール（カーソルが乗っている欄）と上下の矢印（フォーカスのある欄）で増減し、その場で確定する。刻みは 1（key_size、opacity、dim_opacity、辺の数値）、10（latch_ms、hover_ms、slide_ms）、1000（auto_hide_ms）で、Shift を押しながらだと10倍。範囲の端で止まり、0 でオフにできる欄は下限から下げると 0、0 から上げると下限になる
- 「保存しました」など、したことの知らせは、窓の上（見出しの行の右）に色の付いた帯で出し、数秒で消す。直す必要のあること（値の誤り、保存できない理由、外での書き換え）はステータス行に残す
- 保存できなかった時の理由はリンクで出す。押す（フォーカスして Enter でも）と、誤りのある行の項目の画面を開き、その欄にフォーカスを移す（[edge] の行は「辺（共通）」、[edge.*] の行は「辺ごとの設定」でその辺を選ぶ）。[set.*] の行は、layout の行と、キーの幅・位置（width・x・y・w・h、KLE の配列より多い key 行）の誤りは「キー配置」でそのキーを選び、幅か位置の欄にフォーカスを移す。それ以外の誤りは「キーマッピング」で、キーの行ならそのキーを選ぶ。[profile.*] の行は「アプリ別」、欄のない行はそのセクションの画面を開く。理由は表示に残す
- 窓の下端の行に、使っている設定ファイルのフルパス（長いパスは途中を省く）、「テキストで開く」ボタン（トレイの「設定ファイルを開く」と同じく既定のアプリで開く）、「保存」ボタンを並べる
- 画面の内容が、最後に読んだか保存したファイルと違う間は、タイトルの先頭に「●」を付け、保存ボタンを既定のボタンとして強調する。保存するか、変えた値を元に戻すと、どちらも消える
- キーボードだけで操作できる。Tab / Shift+Tab で部品を順に移り、サイドバーは上下の矢印で項目を選び、Space / Enter でボタンを押す。フォーカスのある部品は、キーを押す前から見て分かる。Esc で閉じ、Ctrl+S で保存ボタンと同じ保存をする（入力の途中の欄は、先に確定してから保存する）
- 保存は、書き出す内容をパーサで検証してから設定ファイルへ書き込む。エラーがあれば書き込まず、行と理由を示す。反映は既存の自動再読込に任せる
- 書き戻しでは、変更していない行・コメント・並び順をそのまま残す。手で書いた設定ファイルを画面で直しても壊さない
- 設定ファイルが UTF-8 でない・大きすぎるなど、文書として読めない時は設定画面を開かず、通知で理由を伝える（画面では直せないため）
- 開いている間に設定ファイルが外で書き換わったら知らせ、読み直すか、画面の内容を保つかを選ばせる。設定画面自身の保存は外での書き換えとして扱わない
- ライト / ダークは OS の設定（アプリのモード）に従い、パネルの theme（5.2）には従わない。タイトルバー、背景、標準の部品、自前で描く部分のすべてを揃え、開いている間に OS の設定を切り替えると、すぐに変わる。標準の部品のダークモードは、Windows が文書にしていないテーマ（DarkMode_Explorer）に頼る
- Per-Monitor DPI（5.4）に従う。窓の大きさを変えると部品が並び直し、最小の大きさより小さくはできない
- パネルのキーをマウスで押している間に、指で設定画面のボタンやサイドバーを押しても、マウスのキーはマウスを離すまで押されたまま（指の操作をマウスの操作に変えない）
- 設定画面を閉じると、そのプロセスは終わる。読み込んだ comctl32 v6 とそのテーマ、Windows が読み込む文字入力（IME、Text Input Framework）などの部品もプロセスごと解放され、常駐側には残らない。常駐側が終わると設定画面のプロセスも終わる（トレイの「終了」では、保存していない変更があれば、設定画面が先に問いかけ、EdgePad は終わらない）
- 設定画面を開閉しても、常駐側の状態（ラッチ中の修飾キー、押しているキー、プロファイルの一時固定、一時停止、辺ごとの表示切替）は変わらない
- 常駐側は IME を使わない（パネルとトレイメニューでは文字を打たないため）。設定画面の側では IME を使え、日本語を入力できる

## 8. 非機能要件

軽さの目標は下表のとおりです。いずれも設計上の目標値で、M0のプロトタイプで実測して見直します。待機時CPU・起動時間・ワーキングセットは、常駐している EdgePad の、設定画面（7.1）を一度も開いていない時の値です。プライベートメモリは、常駐側と、設定画面のプロセス（7.1）に分けます。

| 項目 | 目標 | 実現手段 |
|---|---|---|
| 待機時CPU | 0%（タイマー・ポーリングなし） | 全処理をメッセージ駆動。リピートとマウスホバー判定の時だけタイマーを動かす |
| メモリ（プライベート） | 常駐側: 起動直後 2.5MB以下、トレイメニューを開き設定画面を開閉した後も 3MB以下で、開閉を繰り返しても増えない（64KB 以内の揺れは除く）/ 設定画面のプロセス: 開いている間 8MB以下 | ランタイムなし、スレッド1本、ヒープ確保は設定読込時に限定。起動直後は、設定画面を入れた後の実測が2MB前後で揺れるため、当初の2MBから見直した。常駐側は IME を止め、設定画面を別のプロセスにすることで、文字入力の部品（約1MB）と comctl32 v6 を読み込まない（実測 2.3MB） |
| メモリ（ワーキングセット） | 5MB以下 | 非表示中はパネルの描画バッファ（DIB）を解放 |
| exeサイズ | 1MB以下 | 依存は windows-sys のみ、サイズ最適化ビルド。設定画面を本体に内蔵するため、当初の500KBから見直した |
| 起動時間 | 100ms以下 | 設定読込とウィンドウ生成のみ |
| キー反応 | タッチから送出まで1フレーム以内 | 入力スレッドで直接 SendInput、描画は送出の後 |

その他の要件:

- スレッド: UIスレッド1本。ファイル監視も同じメッセージループで MsgWaitForMultipleObjects により待つ
- 安全性: ネットワーク通信なし、外部コードの読込なし。run キーは設定ファイルに書かれたものだけ実行する
- ログ: 既定は出力なし。--debug 起動時のみ同フォルダへテキストログ
- 信頼性: 6.3の解放処理を全終了経路で保証する
- ライセンス: 未定。GitHubの公開リポジトリで公開する

## 9. 開発ステップと未決事項

最初の関門は「フォーカスを奪わないパネルから送ったCtrlが、ペン描画中のCSPに効くか」です。M0でこれを確かめてから機能を積みます。

1. M0 技術検証: 左辺に固定5キー（Esc/Ctrl/Shift/Alt/Space）のパネル。WS_EX_NOACTIVATE＋SendInput でCSPに指Ctrl＋ペン描画が効くこと、メモリとexeサイズを実測
2. M1 最小実用版: 4辺、設定ファイル読込と自動再読込、トレイ常駐、ホットキー、ハンドル操作、押しっぱなし防止
3. M2 キー機能: ラッチ、shortcut / repeat / macro / text / run / page、アプリ別プロファイル自動切替
4. M3 表示の仕上げ: Per-Monitor DPI、マルチモニタ、半透明モード、テーマ、自動起動、ドッキング（AppBar）
   - 追加（M3の後）: パイメニュー（4.6、5.6）
   - 追加（パイメニューの後）: 設定画面（7.1）。本体に内蔵し、exeサイズの目標を1MBに見直す
5. M4 配布: 既定設定（CSP向けプリセット同梱）、説明書、GitHubの公開リポジトリでリリースし、marbyworks.comからリンク
6. 将来: macOS版、Linux（X11）版、アイコン表示
