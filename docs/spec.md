# EdgePad 仕様書

2026年10月22日 · @まーびい

## 1. 概要

EdgePadは、画面の上下左右の端にタッチ・マウス操作できるマクロキーパッドを出す、Windows向けの軽量常駐ソフトです。CLIP STUDIO PAINT（以下CSP）のエッジキーボードはiPad/Androidでしか使えないため、同等の操作感をデスクトップOS、特に液晶タブレットやタッチ対応PCで実現します。

- 目的: 片手（指）で修飾キーやショートカットを押しながら、もう片手（ペン）で描ける環境をデスクトップで作る
- 方針: CSP専用にはせず、前面アプリに普通のキー入力を送る汎用ツールにする。アプリごとにキー配置を自動で切り替える
- 最重要の非機能要件: 待機時CPU 0%、メモリ数MB、単体exe1本

用語:

| 用語 | 意味 |
|---|---|
| パネル | 画面端に表示されるキーの並び（上下左右それぞれ1枚） |
| ハンドル | パネル非表示時に画面端に残る細い帯。ここをスワイプ/タップしてパネルを出す |
| キーセット | 1枚のパネルに並べるキーの定義一式 |
| プロファイル | 前面アプリ（プロセス名）とキーセットの対応 |
| ラッチ | 修飾キーを押しっぱなし状態で固定すること |

## 2. 参考：CSPのエッジキーボード

CSP版の「修飾キー＋タッチキー1〜15、端からのスワイプで表示、短いスワイプで半透明」という骨格はそのまま踏襲します。公式マニュアルでも、Windowsタブレットとタッチ対応の液晶タブレットでは使えないと明記されています（公式マニュアル）。

| 項目 | CSP（iPad/Android） | EdgePad |
|---|---|---|
| 対応環境 | iPad / Androidタブレット | Windows 10/11（将来 macOS / Linux） |
| 表示位置 | 左右の端 | 上下左右の4辺、辺ごとに独立 |
| 固定キー | Esc / Ctrl / Shift / Alt（option）/ Space（iPadはcommandも） | 既定は同じ並び。全キー自由に変更可 |
| タッチキー | 1〜15。CSPのショートカット設定で割り当て | キー自体にキー送出・マクロ等を定義（CSP側の設定不要） |
| 表示 | 端から内側へスワイプ（Androidは切替ボタン） | ハンドルのスワイプ/タップ、ホットキー、マウスの端ホバー、トレイ |
| 半透明表示 | 短いスワイプで半透明。指は操作可、ペンは下のキャンバスへ | 同じ操作で半透明。ペンは透過させず、キーにも反応しない |
| 非表示 | 端の方向へスワイプ | 同じ。加えてホットキー・自動非表示 |
| 対象アプリ | CSPのみ | 前面の任意アプリ。アプリ別に自動切替 |

CSPのタッチキー1〜15はアプリ内部の特殊キーなので、外部ソフトから同じキーは作れません。代わりに、各キーに「Ctrl+Z を送る」のような動作を直接持たせます。CSP側のショートカットに割り当てたい場合は、通常のキーボードにないF13〜F24を送る運用も選べます（CSPのショートカット設定で登録できることを確認済み）。

## 3. 対象環境と技術方針

Rust＋Win32 APIの直接呼び出しで作り、GUIフレームワークやランタイム（.NET、Electron、WebView）は一切使いません。これがメモリ数MB・exe 1MB以下に収める前提です。

| 項目 | 方針 |
|---|---|
| 初期対象OS | Windows 10 21H2以降 / Windows 11（x64。ARM64は優先度低） |
| 言語 | Rust（stable）。依存クレートは windows-sys のみを原則とする |
| 描画 | GDI＋UpdateLayeredWindow（32bit DIBでアルファ付き）。変化があった時だけ再描画 |
| 入力受付 | WM_POINTER 系メッセージ。タッチ・ペン・マウスを種別付きで受ける |
| キー送出 | SendInput（仮想キー、文字は KEYEVENTF_UNICODE） |
| 前面アプリ検出 | SetWinEventHook(EVENT_SYSTEM_FOREGROUND)。ポーリングしない |
| 設定 | テキストのINI風ファイルを自前パーサで読む（serde/toml を入れない） |
| ビルド | opt-level="z"、LTO、codegen-units=1、panic="abort"、strip、CRT静的リンク |
| 配布 | 単体exe＋設定ファイル1つ。インストーラなし、ポータブル動作可 |

将来のmacOS/Linux対応に備え、OSに依存しない「コア」と、OSごとの「プラットフォーム層」を分けます。コアはキー定義・修飾キーの状態管理・レイアウト計算・設定読込を持ち、OS APIを呼びません。

| 層 | 担当 | Windows実装 | 将来の移植先 |
|---|---|---|---|
| コア | 設定、キーセット、修飾キー状態機械、レイアウト、ジェスチャ判定 | 共通 | 共通 |
| ウィンドウ/描画 | 前面固定・非アクティブのパネル、ハンドル | Win32＋GDI | macOS: 非アクティブNSPanel / Linux: X11 override-redirect、Wayland layer-shell |
| キー送出 | 仮想キーの押下・解放 | SendInput | macOS: CGEventPost（アクセシビリティ許可が必要）/ X11: XTest / Wayland: uinput か libei |
| 前面アプリ検出 | プロファイル切替 | WinEventHook | macOS: NSWorkspace通知 / X11: _NET_ACTIVE_WINDOW |
| 常駐UI | トレイアイコン、ホットキー | Shell_NotifyIcon、RegisterHotKey | 各OSの同等機能 |

Waylandはセキュリティ上、他アプリへのキー送出と前面アプリ取得に標準手段がないため、Linux対応はX11を先に行います。

入力から送出までは1本のメッセージループで処理します。設定変更と前面アプリの切替は、コアが持つキーセットを入れ替えるだけです。

## 4. 機能要件

### 4.1 パネルと常駐

- 上下左右の各辺にパネルを1枚ずつ持てる。辺ごとに有効/無効、対象モニタ、キーセットを設定する
- 起動するとタスクトレイに常駐し、タスクバーには出ない
- トレイメニュー: 各辺の表示切替、プロファイル一時固定、設定…（設定画面を開く、7.1）、設定ファイルを開く、設定再読込、一時停止、全キー解放、Windows起動時に自動起動、終了
- 多重起動しない（名前付きミューテックス）。2回目の起動は既存インスタンスのパネル表示切替として扱う

### 4.2 キーの種類

| 種類 | 動作 | 例 |
|---|---|---|
| modifier | 押している間だけ押下。短くタップするとラッチ（再タップで解除） | Ctrl, Shift, Alt, Win |
| hold | 押している間だけ押下。ラッチしない | Space（手のひらツール） |
| shortcut | 離した時に1回送出。ラッチ中の修飾キーと合成 | Ctrl+Z, Ctrl+Shift+S |
| repeat | 押している間オートリピート | [ ]（ブラシサイズ）, 矢印 |
| macro | 複数のキー操作を待ち時間付きで順に送出 | Ctrl+A → Ctrl+C |
| text | 文字列をUnicode入力で送る | 定型文 |
| run | プログラムやURLを起動 | 電卓、資料フォルダ |
| page | パネル内のページ切替、別キーセットへ切替 | 次ページ |
| pie | 押した位置にパイメニューを開き、滑らせた方向の項目を離した時に実行 | 変形メニュー |

### 4.3 修飾キーの挙動

指で押さえたままペンで描く使い方を最優先にします。マウス操作では「押さえたまま他を操作」ができないため、タップでのラッチを必須とします。

| 操作 | 結果 |
|---|---|
| 押して離す（250ms未満、他のキー操作なし） | ラッチ。キーは押下状態のまま強調表示 |
| ラッチ中にもう一度タップ | 解除（キーアップ送出） |
| 押したまま（250ms以上） | 押している間だけ押下。離すとキーアップ |
| ラッチ中にshortcutキーを押す | 合成して送出後、ラッチを自動解除（ワンショット）。常時固定は設定で選択 |
| パネル非表示、プロファイル切替、画面ロック、終了 | 押下中の全キーを必ず解放 |

### 4.4 キーセットとプロファイル

- キーセットはページを持てる。表示しきれないキーは次ページへ送る
- プロファイルはプロセス名（例: CLIPStudioPaint.exe）で前面アプリと照合し、辺ごとのキーセットを自動で切り替える
- どのプロファイルにも当たらない時は default を使う。プロファイル側で「このアプリではパネルを出さない」も指定できる
- トレイから現在のプロファイルを一時固定できる（ダイアログ操作中の誤切替防止）

### 4.5 表示・非表示の操作

| 操作 | 結果 |
|---|---|
| ハンドルから内側へ長くスワイプ | 通常表示 |
| ハンドルから内側へ短くスワイプ | 半透明表示 |
| 半透明時に同じ方向へスワイプ | 通常表示へ |
| パネル上で端の方向へスワイプ | 非表示（半透明時も同じ） |
| ハンドルをタップ / クリック | 表示切替 |
| マウスを辺に一定時間当てる（任意） | 表示。離れて一定時間で非表示 |
| グローバルホットキー（例: Ctrl+Alt+E） | 全辺の表示切替 |
| 最後の操作から一定時間（任意、既定オフ） | 自動で非表示 |

### 4.6 パイメニュー

pie キーは、別のキーセットを項目にしたパイメニューを開きます。パネルに並べきれない操作を、1キー分の場所から方向で選べるようにします。

- 項目は参照先キーセットのキーを先頭から順に使う。キーは2〜8個で、それ以外は読込エラー（9個以上のセットの先頭8個だけを使うことはしない）。項目の種類は shortcut / macro / text / run / page に限る（離した時に1回実行するため）。modifier / hold / repeat / pie と、項目数の誤りは読込エラー
- 押した位置から画面の内側へ向けて扇形に開く（左辺なら右半分）。項目は扇の角度を等分して並べる
- 方向の判定は押した位置からの移動量で行う。中央（半径はキー1辺の半分）と、端の側（扇の外）で離すと取消

| 操作 | 結果 |
|---|---|
| pie キーを押したまま滑らせて離す | 指している項目を実行して閉じる |
| 中央または端の側で離す | 何もせず閉じる |
| タップ（中央から動かさずに離す） | 開いたまま。項目をタップで実行、中央か pie キーのタップで閉じる |
| ラッチ中の修飾キーがある | shortcut と同じく合成して送出、ワンショット解除 |
| パネル非表示、プロファイル切替、画面ロック、スリープ、終了 | 何も実行せず閉じる |

- pie キーを押している指は、端の方向へ動かしてもパネルを隠さない（4.5 のフリックの対象外）
- ペンでは開かない（pen_presses の設定に従う）
- 開いたままの時に扇の外をタップしても閉じない。その入力は下のアプリへ届き、パイメニューは入力を奪わない

## 5. UI仕様

### 5.1 ハンドル

- 非表示時、有効な辺に幅4〜8px（設定可）の細い帯を出す。長さは辺の中央40%を既定とし、位置と長さは設定で変更できる
- Windowsのタッチ環境では画面端からのスワイプがOS（ウィジェット、通知センター等）に取られる。このためハンドルは画面のきわではなく、ハンドル自体を起点にしたスワイプで判定する
- ハンドルは描画をほぼ持たない（単色＋不透明度30%程度）。不要なら非表示にしてホットキーのみで運用できる

### 5.2 パネル

- 左右のパネルは縦並び、上下のパネルは横並び。列数（左右）と行数（上下）は1〜3で設定
- キーは正方形を基本とし、1辺は既定56論理px（DPIに比例）。キーごとに幅を2倍などに広げられる
- 表示要素は「ラベル文字」「押下状態」「ラッチ状態」の3つだけ。アイコン画像は後回し（必要ならPNG読込を拡張で追加）
- 配色はライト/ダーク2種＋アクセント1色。OSのダークモード設定に追従（任意）
- 通常表示の不透明度は既定90%、半透明表示は既定35%
- 表示/非表示はアニメーションなし（軽さ優先）。任意で100ms程度のスライドを選べる

### 5.3 ウィンドウ属性

| 属性 | 目的 |
|---|---|
| WS_EX_NOACTIVATE | 押してもフォーカスを奪わない。キーが前面アプリに届く前提 |
| WS_EX_TOPMOST | 常に最前面 |
| WS_EX_TOOLWINDOW | タスクバー・Alt+Tabに出さない |
| WS_EX_LAYERED | アルファ付き描画、半透明表示 |

### 5.4 モニタとDPI

- Per-Monitor DPI Aware V2 を宣言し、モニタ移動やスケール変更（WM_DPICHANGED）で再レイアウトする
- 辺ごとに対象モニタを primary / 番号 / cursor（表示時にカーソルがあるモニタ）から選ぶ
- モニタ構成の変更（WM_DISPLAYCHANGE）で位置を再計算する

### 5.5 ドッキングモード（任意）

既定はキャンバスの上に重ねるオーバーレイ表示です。設定で辺をAppBar（SHAppBarMessage）として登録すると、最大化ウィンドウがパネルの分だけ縮み、キャンバスを隠しません。デスクトップならではの選択肢として用意します。

### 5.6 パイメニュー

- パネルと同じ属性（5.3）の窓を、開いている間だけ作る。閉じたら窓と描画バッファを解放する
- 押した位置を中心とする半円のドーナツ形のタッチエリアを、項目ごとの扇形の区画に分ける。区画の外は透明
  - 区画どうしはパネルのキーの間と同じ幅のすき間で区切る。中央の取消範囲（半径はキー1辺の半分）は穴として抜く
  - 外径はキー2個分以上。項目が多い時は、ラベルを置く位置（穴と外周の中間）で区画の幅がキー1個分以上になるまで大きくする
  - 縁は1ピクセルずつ覆う割合を計算して滑らかに描く（GDIの扇形はアンチエイリアスが効かないため使わない）。ラベルの文字だけGDIで描く
- 表示要素は区画と項目のラベル文字、指している項目の強調だけ。区画はキーの面、強調は押しているキーと同じ色。配色と不透明度はパネルに合わせる
- 開く時に遅延やアニメーションは入れない。タイマーを使わない

## 6. キー送出とフォーカス制御

パネルはフォーカスを持たず、SendInput で送ったキーはそのとき前面にあるアプリ（例: CSP）に届きます。押下状態はOS全体で共有されるため、指でCtrlを押さえている間にペンでキャンバスを操作すれば、CSPからはCtrl＋ペン操作に見えます。

### 6.1 入力の受け方

- WM_POINTERDOWN / UPDATE / UP を使い、ポインタIDごとに追跡する。複数の指で複数キーを同時に押せる
- ポインタ種別（タッチ / ペン / マウス）ごとに「キーを押せるか」を設定できる。既定はタッチとマウスのみ可、ペンは不可（誤タッチ防止）
- 押したままキーの外へ指が出ても、指を離すまで押下を維持する（描画中の手のずれ対策）
- パネルへのタッチがOSのマウス操作に変換されないよう、ポインタメッセージを自前で処理して既定処理へ流さない

### 6.2 送出の規則

- 修飾キーの押下は、自分が送ったものだけを記録して管理する。物理キーボードで押されている修飾キーには触れない
- shortcutは「ラッチ中修飾キー＋定義上の修飾キー」を押下 → 本キー押下 → 本キー解放 → 定義上の修飾キー解放、の順に送る
- 拡張キー（矢印、Insert、Delete等）は KEYEVENTF_EXTENDEDKEY を付け、スキャンコードも併せて送る（ゲーム系・一部アプリ対策）
- 送出イベントには独自の dwExtraInfo 値を付け、自分の入力と区別できるようにする

### 6.3 押しっぱなし事故の防止

キーが押下されたまま残ると、OS全体の操作が狂うため最優先で防ぎます。

- パネル非表示、プロファイル切替、WM_WTSSESSION_CHANGE（ロック・ユーザー切替）、スリープ移行、終了の各時点で、自分が押下中の全キーを解放する
- パニック時もフックで解放してから終了する（panic="abort" でもパニックフックは実行される）
- トレイメニューに「全キー解放」を置く

### 6.4 権限の制約

Windowsの仕様（UIPI）により、通常権限のEdgePadからは管理者権限で動くアプリへキーを送れません。管理者アプリに使う場合はEdgePadも管理者で起動する必要があります。設定ドキュメントに明記し、送出に失敗した時はトレイ通知で知らせます。

## 7. 設定ファイル仕様

設定はUTF-8のテキスト1ファイル（edgepad.ini）で行います。テキストエディタで直接書くほか、本体に内蔵した設定画面（7.1）でも全項目を編集できます。exeと同じフォルダに置けばポータブル動作、なければ %APPDATA%\EdgePad\edgepad.ini を使います。

- 保存を検知して自動で再読込する（FindFirstChangeNotification、待機はイベント駆動）
- 読込エラー時は直前の設定のまま動き続け、トレイ通知に行番号と理由を出す
- キー名はWindowsの仮想キー名に準じた英字表記（Ctrl, Shift, Alt, Win, A〜Z, F1〜F24, Space, Enter, Esc, Left, PgUp 等）。+ で組み合わせる
- 1行1キーで `key = ラベル | 種類 | 内容 | オプション` と書く

```ini
[general]
hotkey        = Ctrl+Alt+E   ; 全辺の表示切替
key_size      = 56           ; キー1辺（論理px）
opacity       = 90           ; 通常表示の不透明度 %
dim_opacity   = 35           ; 半透明表示の不透明度 %
latch_ms      = 250          ; これ未満のタップでラッチ
pen_presses   = false        ; ペンでキーを押せるか
theme         = auto         ; light / dark / auto

[edge.left]
enabled  = true
monitor  = primary           ; primary / 1,2... / cursor
columns  = 1
handle   = 6, 40%            ; ハンドル幅px, 長さ

[edge.right]
enabled  = true
monitor  = primary
columns  = 2

[set.mods]
key = Esc   | shortcut | Esc
key = Ctrl  | modifier | Ctrl
key = Shift | modifier | Shift
key = Alt   | modifier | Alt
key = Space | hold     | Space

[set.csp-tools]
key = 元に戻す | shortcut | Ctrl+Z
key = やり直し | shortcut | Ctrl+Y
key = ブラシ小 | repeat   | [        | interval=60
key = ブラシ大 | repeat   | ]        | interval=60
key = 選択解除 | shortcut | Ctrl+D
key = 左右反転 | shortcut | F13      ; CSP側でF13に割り当てる運用
key = 保存     | macro    | Ctrl+S, wait 300, Esc
key = 次へ     | page     | next
key = 変形     | pie      | csp-transform

[set.csp-transform]                ; pie の項目（先頭から2〜8個）
key = 拡大縮小 | shortcut | Ctrl+T
key = 上下反転 | shortcut | F14
key = 回転戻し | shortcut | F15
key = 確定     | shortcut | Enter

[profile.default]
left  = mods
right = none

[profile.csp]
process = CLIPStudioPaint.exe
left    = mods
right   = csp-tools
```

キーセットは複数の辺で共有できます。none を指定した辺はそのプロファイル中は表示しません。

### 7.1 設定画面

設定ファイルの全項目を、テキストを書かずに編集する画面です。別exeやWebページにはせず本体に内蔵します。

- トレイメニューの「設定…」で開く通常のウィンドウ。同じ exe を、設定画面だけを出す2つ目のプロセスとして起動して出す（パネル・トレイアイコン・ホットキーは持たず、多重起動防止にも当たらない）。開いている間はこのウィンドウだけタスクバーと Alt+Tab に出る。すでに開いていれば、そのウィンドウを前に出す（二重には開かない）
- 設定画面が前面になっても、プロファイルは切り替えない（EdgePad 自身のウィンドウは 4.4 の前面アプリとして数えない）。キーの押下もそのまま
- ボタン・入力欄・ドロップダウン・チェックボックス・一覧・サイドバーには OS 標準の部品を使う（Windows は comctl32 v6 の見た目）。自前で描くのは、パネルの見本や画面の図のように標準の部品にないものだけにする。comctl32 v6 は設定画面を初めて開いた時に読み込み、起動時には読み込まない
- 窓の左のサイドバーに「キー配置」「アプリ別」「辺と表示」「操作」の4項目が並び、選んだ画面が右側に出る。開いた時は「キー配置」を出す。画面は設定ファイルの章立てではなく、やりたいことで分け、合わせて全項目を編集できる
  - キー配置: キーセットとキー（[set.*]）
  - アプリ別: プロファイル（[profile.*]）
  - 辺と表示: 辺ごとの項目（[edge.*]）と、見た目の項目（[general] の key_size、opacity、dim_opacity、theme、accent、slide_ms）
  - 操作: 操作の項目（[general] の latch_ms、latch、pen_presses、hotkey、hover_ms、auto_hide_ms）
- 「辺と表示」と「操作」は、項目ごとの欄（項目名、入力欄、書ける範囲、既定値か「既定に戻す」）。数値と文字は入力欄、選択肢はドロップダウン、オン / オフはチェックボックス
  - 「辺と表示」の辺の項目は、画面を表す四角と4辺の図で辺を選んでから編集する。図は有効な辺を塗りつぶし、無効な辺を線だけで描き、選んでいる辺を強調し、ハンドルの位置と長さを辺の上に示す。辺を押すか、図にフォーカスがある時に ←→↑↓ で選ぶ。欄を変えると図もすぐに変わる
  - 設定ファイルに書いていない項目は、既定値を「既定値」と添えて出す。「既定に戻す」はその項目の行をファイルから消す。開いている間に外での書き換えを読み直すと、欄も新しい値になる
  - 欄を変えると、その項目の行だけを書き換える（ほかの行、コメント、その行の行末コメントは残す）。ファイルにない項目やセクションは追加する
  - 範囲外や形式の違う値は入力欄で止める。欄を誤りの表示にし、ステータス行に理由を出し、ファイルには書かない。文字と数値の欄は Enter かフォーカスが外れた時に確定する
  - 数値の欄は、マウスのホイール（カーソルが乗っている欄）と上下の矢印（フォーカスのある欄）で増減し、その場で確定する。刻みは 1（key_size、opacity、dim_opacity、辺の数値）、10（latch_ms、hover_ms、slide_ms）、1000（auto_hide_ms）で、Shift を押しながらだと10倍。範囲の端で止まり、0 でオフにできる欄は下限から下げると 0、0 から上げると下限になる
- 保存できなかった時の理由はリンクで出す。押す（フォーカスして Enter でも）と、誤りのある行の項目の画面を開き、その欄にフォーカスを移す（辺の項目はその辺を選ぶ）。[set.*] の行は「キー配置」、[profile.*] の行は「アプリ別」、欄のない行はそのセクションの画面を開く。理由は表示に残す
- 窓の下端の行に、使っている設定ファイルのフルパス（長いパスは途中を省く）、「テキストで開く」ボタン（トレイの「設定ファイルを開く」と同じく既定のアプリで開く）、「保存」ボタンを並べる
- 画面の内容が、最後に読んだか保存したファイルと違う間は、タイトルの先頭に「●」を付け、保存ボタンを既定のボタンとして強調する。保存するか、変えた値を元に戻すと、どちらも消える
- キーボードだけで操作できる。Tab / Shift+Tab で部品を順に移り、サイドバーは上下の矢印で項目を選び、Space / Enter でボタンを押す。フォーカスのある部品は、キーを押す前から見て分かる。Esc で閉じ、Ctrl+S で保存ボタンと同じ保存をする（入力の途中の欄は、先に確定してから保存する）
- 保存は、書き出す内容をパーサで検証してから設定ファイルへ書き込む。エラーがあれば書き込まず、行と理由を示す。反映は既存の自動再読込に任せる
- 書き戻しでは、変更していない行・コメント・並び順をそのまま残す。手で書いた設定ファイルを画面で直しても壊さない
- 設定ファイルが UTF-8 でない・大きすぎるなど、文書として読めない時は設定画面を開かず、通知で理由を伝える（画面では直せないため）
- 開いている間に設定ファイルが外で書き換わったら知らせ、読み直すか、画面の内容を保つかを選ばせる。設定画面自身の保存は外での書き換えとして扱わない
- ライト / ダークは OS の設定（アプリのモード）に従い、パネルの theme（5.2）には従わない。タイトルバー、背景、標準の部品、自前で描く部分のすべてを揃え、開いている間に OS の設定を切り替えると、すぐに変わる。標準の部品のダークモードは、Windows が文書にしていないテーマ（DarkMode_Explorer）に頼る
- Per-Monitor DPI（5.4）に従う。窓の大きさを変えると部品が並び直し、最小の大きさより小さくはできない
- パネルのキーをマウスで押している間に、指で設定画面のボタンやサイドバーを押しても、マウスのキーはマウスを離すまで押されたまま（指の操作をマウスの操作に変えない）
- 設定画面を閉じると、そのプロセスは終わる。読み込んだ comctl32 v6 とそのテーマ、Windows が読み込む文字入力（IME、Text Input Framework）などの部品もプロセスごと解放され、常駐側には残らない。常駐側が終わると設定画面のプロセスも終わる（トレイの「終了」では、保存していない変更があれば、設定画面が先に問いかけ、EdgePad は終わらない）
- 設定画面を開閉しても、常駐側の状態（ラッチ中の修飾キー、押しているキー、プロファイルの一時固定、一時停止、辺ごとの表示切替）は変わらない
- 常駐側は IME を使わない（パネルとトレイメニューでは文字を打たないため）。設定画面の側では IME を使え、日本語を入力できる

## 8. 非機能要件

軽さの目標は下表のとおりです。いずれも設計上の目標値で、M0のプロトタイプで実測して見直します。待機時CPU・起動時間・ワーキングセットは、常駐している EdgePad の、設定画面（7.1）を一度も開いていない時の値です。プライベートメモリは、常駐側と、設定画面のプロセス（7.1）に分けます。

| 項目 | 目標 | 実現手段 |
|---|---|---|
| 待機時CPU | 0%（タイマー・ポーリングなし） | 全処理をメッセージ駆動。リピートとマウスホバー判定の時だけタイマーを動かす |
| メモリ（プライベート） | 常駐側: 起動直後 2.5MB以下、トレイメニューを開き設定画面を開閉した後も 3MB以下で、開閉を繰り返しても増えない（64KB 以内の揺れは除く）/ 設定画面のプロセス: 開いている間 8MB以下 | ランタイムなし、スレッド1本、ヒープ確保は設定読込時に限定。起動直後は、設定画面を入れた後の実測が2MB前後で揺れるため、当初の2MBから見直した。常駐側は IME を止め、設定画面を別のプロセスにすることで、文字入力の部品（約1MB）と comctl32 v6 を読み込まない（実測 2.3MB） |
| メモリ（ワーキングセット） | 5MB以下 | 非表示中はパネルの描画バッファ（DIB）を解放 |
| exeサイズ | 1MB以下 | 依存は windows-sys のみ、サイズ最適化ビルド。設定画面を本体に内蔵するため、当初の500KBから見直した |
| 起動時間 | 100ms以下 | 設定読込とウィンドウ生成のみ |
| キー反応 | タッチから送出まで1フレーム以内 | 入力スレッドで直接 SendInput、描画は送出の後 |

その他の要件:

- スレッド: UIスレッド1本。ファイル監視も同じメッセージループで MsgWaitForMultipleObjects により待つ
- 安全性: ネットワーク通信なし、外部コードの読込なし。run キーは設定ファイルに書かれたものだけ実行する
- ログ: 既定は出力なし。--debug 起動時のみ同フォルダへテキストログ
- 信頼性: 6.3の解放処理を全終了経路で保証する
- ライセンス: 未定。GitHubの公開リポジトリで公開する

## 9. 開発ステップと未決事項

最初の関門は「フォーカスを奪わないパネルから送ったCtrlが、ペン描画中のCSPに効くか」です。M0でこれを確かめてから機能を積みます。

1. M0 技術検証: 左辺に固定5キー（Esc/Ctrl/Shift/Alt/Space）のパネル。WS_EX_NOACTIVATE＋SendInput でCSPに指Ctrl＋ペン描画が効くこと、メモリとexeサイズを実測
2. M1 最小実用版: 4辺、設定ファイル読込と自動再読込、トレイ常駐、ホットキー、ハンドル操作、押しっぱなし防止
3. M2 キー機能: ラッチ、shortcut / repeat / macro / text / run / page、アプリ別プロファイル自動切替
4. M3 表示の仕上げ: Per-Monitor DPI、マルチモニタ、半透明モード、テーマ、自動起動、ドッキング（AppBar）
   - 追加（M3の後）: パイメニュー（4.6、5.6）
   - 追加（パイメニューの後）: 設定画面（7.1）。本体に内蔵し、exeサイズの目標を1MBに見直す
5. M4 配布: 既定設定（CSP向けプリセット同梱）、説明書、GitHubの公開リポジトリでリリースし、marbyworks.comからリンク
6. 将来: macOS版、Linux（X11）版、アイコン表示
