# 実測結果

仕様書 8 章の軽さの目標と、M0（v0.1）の技術検証の結果を記録する。数値は `ci/measure.py` で測り直せる。

## v0.1（2026-10-22）

### 環境

| 項目 | 値 |
|---|---|
| OS | Windows 11 26H2（build 26300） |
| CPU | 12th Gen Intel Core i7-1250U |
| 画面 | 1920x1080、96 DPI（100%） |
| 測定した exe | main の 5c1d3cc を `cargo build --release` したもの |

### 手順

```
cargo build --release
python ci/measure.py
```

仕様書の KB・MB は KiB・MiB（1024 単位）として扱う。起動時間は起動呼び出しの直前から測るので、プロセス生成の時間も含み、遅めに出る。

スクリプトは exe を起動し、パネルが表示されるまでの時間を測る。その後 60 秒待機させ、待機中の CPU 時間、待機後のプライベートメモリとワーキングセットを読む。最後にプロセスを止める。

### 結果

| 項目 | 実測 | 目標（仕様書 8 章） | 判定 |
|---|---|---|---|
| exe サイズ | 206 KiB（211,456 bytes） | 500 KiB 以下 | 達成 |
| 起動時間（起動からパネル表示まで） | 27.5 ms | 100ms 以下 | 達成 |
| プライベートメモリ | 1.60 MiB | 2 MiB 以下 | 達成 |
| ワーキングセット | 11.02 MiB | 5 MiB 以下 | **未達** |
| 待機時 CPU（60 秒間の CPU 時間） | 0.0 ms | 0%（タイマー・ポーリングなし） | 達成 |

### 未達の項目

**ワーキングセット 11.02 MiB（目標 5MB 以下）**

- 原因の見立て: 大半は共有のシステム DLL のページで、EdgePad 自身のデータではない。プライベートメモリは 1.60 MiB に収まっている。トレイアイコン（Shell_NotifyIcon）が shell32.dll と windows.storage.dll を読み込み、この2つだけで読み込みサイズは約16MBある。トレイを入れる前（#3 の時点）のワーキングセットは 8.4MB だった。
- 裏付け: 外から EmptyWorkingSet をかけると、ワーキングセットはほぼ 0 まで下がる。初期化で一度触れただけのページが残っている状態で、常に使われているわけではない。
- 対処の予定: [#10](https://github.com/marby3/EdgePad/issues/10)（v1.0、priority: low）で、初期化の後にワーキングセットを一度縮める方法を試し、待機中の値を測り直す。

## M0 の技術検証: CSP での実機確認

M0 の問いは「フォーカスを奪わないパネルから送ったキーが、ペン描画中の CSP に効くか」だった。答えは「効く」。

- 確認日: 2026-10-22
- 機材: 開発者の手元の、ペンとタッチが使える環境（Windows 11）
- EdgePad: main の 5c1d3cc（v0.1 の内容）

| 操作 | 期待 | 結果 |
|---|---|---|
| 左端の Space を指で押したまま、ペンでキャンバスをドラッグ | 手のひらツールでキャンバスが動く | 効いた |
| 左端の Alt を指で押したまま、ペンでキャンバスをクリック | スポイトで色を拾う | 効いた |
| Alt から指を離す | メニューバーにフォーカスが移らない | 移らなかった |
| Space・Alt から指を離す | キーが戻る（離した後のペンは通常の描画に戻る） | 戻った |

指を離したときにキーアップが1回送られることは、自動テスト（`crates/edgepad/tests/press.rs` の AC1）でも確かめている。

この結果から、WS_EX_NOACTIVATE のパネルと SendInput の組み合わせで、仕様どおりの「指で修飾キー、ペンで描画」が成り立つと判断する。v0.2 以降はこの方式のまま機能を積む。

## v0.2（2026-10-22）

v0.2 の機能（4辺のパネル、設定ファイルと自動再読込、トレイメニュー、ホットキー、ハンドル、ロック・スリープでの解放）がそろった時点で測り直した。

### 環境

v0.1 と同じ機材。測った exe は、main の aa55f78 に [#34](https://github.com/marby3/EdgePad/issues/34) の変更を加え、`cargo build --release` したもの。

### 手順

```
cargo build --release
python ci/measure.py --settings ci/example.ini
```

`ci/example.ini` は仕様書 7 章の設定の例。v0.2 は既定のプロファイルだけを使うので、左に5キーのパネルが1枚出て、ホットキー（Ctrl+Alt+E）も登録される。測定スクリプトは EdgePad を専用の %APPDATA% で起動するので、手元で EdgePad が動いていても測れる。

### 結果

| 項目 | v0.1 | v0.2 | 目標（仕様書 8 章） | 判定 |
|---|---|---|---|---|
| exe サイズ | 206 KiB | 302 KiB | 500 KiB 以下 | 達成 |
| 起動時間 | 27.5 ms | 32.1 ms | 100ms 以下 | 達成 |
| プライベートメモリ | 1.60 MiB | 1.83 MiB | 2 MiB 以下 | 達成（残り 0.17 MiB） |
| ワーキングセット | 11.02 MiB | 12.64 MiB | 5 MiB 以下 | **未達**（#10） |
| 待機時 CPU（60 秒間の CPU 時間） | 0.0 ms | 0.0 ms | 0% | 達成 |

- 設定ファイルなし（固定の5キー）で測ると、プライベートメモリは 1.81〜1.90 MiB だった。設定の有無より、測るたびの揺れのほうが大きい。
- 待機時 CPU は、5回測って3回が 0.0 ms、2回が 15.6 ms と 62.5 ms だった。15.6 ms は Windows のスケジューラの1刻みで、60 秒の間に1〜4回起こされたことになる。続けて測ると 0.0 ms に戻るので、システム全体への通知のような、たまたまの起床と見ている。タイマーやポーリングは使っていない。
- プライベートメモリは、CI の検査（`ci/test_measure.py`）で毎回測り、2 MiB を超えたら落とす。CI では待機 5 秒で測り、測った値を CI のログに出す（「private memory: … bytes」）。手元の待機 5 秒では 1.93 MiB（2,019,328 bytes）で、目標まで 76 KiB しかない。
- `--settings` を渡すと、設定ファイルのホットキーが登録されたかも報告する。設定が読めずに固定の5キーへ戻ると、ホットキーがないので分かる。ほかのアプリがそのホットキーを先に持っていると「taken by another app」と出て、その時は設定が読めたかを確かめられない。
